# CLI daemon — [cli/](cli/)

Moved out of the root `CLAUDE.md` so it loads only when work touches `cli/`.

Milestone 8. A single static Go binary, `wizard`, that manages the backend and frontend as a background service — the primary path now that Milestone 3 made Docker opt-in. `docker compose up` still works; `wizard init && wizard start` is the new one-command path. See [cli/README.md](cli/README.md) for the full subcommand reference and build/cross-compile instructions; this section is the architecture summary.

**Go, not Rust.** Cross-compiles to all three target OSes from one machine via `GOOS`/`GOARCH` with no target toolchain install, `CGO_ENABLED=0` gives a true static binary, and the stdlib (`os/exec`, `net/http`, `os.UserConfigDir`, goroutines) covers process supervision, health polling and log tailing without extra dependencies — the whole job this milestone asks for.

- **`internal/appdir`** is a Go port of `backend/src/utils/appdirs.py`'s `config_dir()`, kept in lockstep by hand since a Go process cannot import the Python module. Same `WIZARD_CONFIG_DIR` override, same per-platform default. Milestone 8 adds `run/` (pid files, the stop sentinel, the crash marker), `logs/` and `venv/` under it, beside `credentials.json`/`connections.json`/`skills/` from earlier milestones.
- **`wizard start` re-execs itself** into a detached, hidden `__supervise` subcommand, so the supervision loop in `internal/daemon` survives the `start` command returning — `start` itself only launches it, polls `/health` until the backend answers, checks the version-compat marker, and opens a browser.
- **The supervisor polls, it doesn't just watch for exit.** A process that hangs without exiting is not caught by "did the child die" — so `internal/daemon.Run` polls `GET /health` (the frontend, which has no equivalent route, gets a bare TCP reachability check instead) and restarts either child with capped exponential backoff on a failure streak, the same as it does on an outright crash. Once the restart budget is exhausted it writes a `crashed` marker and stops trying, rather than either retrying forever or silently going quiet — `wizard status` reads that marker.
- **Per-OS process control is split by build-tag filename** (`process_unix.go` / `process_windows.go`), the same pattern `backend/src/core/security/sandbox/` already uses for the same reason. POSIX: a process group, `SIGTERM` then `SIGKILL`. Windows attempts `CTRL_BREAK_EVENT` first — the same technique `core/tools/host_runtime.py` uses to interrupt one execution — but `GenerateConsoleCtrlEvent` only reaches a process sharing a console with the caller, and the detached, consoleless `__supervise` process this package actually runs as never does; in the shipped binary the stop path is `taskkill /T /F` once the grace period elapses, every time, not "usually graceful."
- **No new backend field for version compatibility.** `internal/compat` compares only the *major* component of `API_VERSION` (`backend/src/api/routes/meta.py`, already reported by both `/health` and `/api/config`) against this binary's build-time compat marker (`-ldflags -X`), so a routine backend patch/minor bump does not force a CLI rebuild. `wizard start` refuses to leave a mismatched pair running.
- **Release awareness and binary updates are supported for managed installs.** The tagged-release workflow stamps a build version and publishes platform archives plus `SHA256SUMS`. `wizard update --check` performs the explicit bounded availability request; `wizard update` stages, verifies, prepares, and safely advances a managed release while retaining its previous package. A source checkout deliberately continues to use Git. Artifact signing remains a release-infrastructure follow-up; do not claim the checksum file is a signature. Unattended system changes remain out of scope (`wizard init` asks before installing prerequisites interactively and requires `--install-prerequisites` for scripts), as does owning the Docker daemon's own lifecycle (`start`/`doctor` only probe reachability; when `docker` is unavailable, the backend selects its supported in-process fallback).
- **No remote access.** The daemon binds `127.0.0.1` only, backend and frontend both — confirmed out of scope by the evolution spec, not a gap.

**Install, packaging and diagnostics (v1.0.13).** The rules below exist because each was a real defect.

- **Who owns the files.** `internal/installkind.Detect` classifies an installation by layout alone (Homebrew keg, Scoop app, the official installer's `<install>/current` + `<install>/bin`, git checkout, unknown). `update` and `uninstall` refuse to modify package-manager files and print that manager's command; `uninstall` never `RemoveAll`s an install root, only its known children, and unlinks `current` (a symlink, or a junction on Windows) before anything else so it is never followed into a package.
- **One target matrix.** `packaging/release.json` lists the supported OS/arch pairs and the artifact name template. `internal/platform` mirrors it and a test fails on drift; `scripts/build_release.sh`, `scripts/release.py` and both installers read or are checked against it. Artifact names (`Wizard-<tag>-<goos>-<goarch>.zip`) are frozen for 1.0.x because CLIs already in the field look them up when they self-update.
- **`SHA256SUMS` lists bare names.** `sha256sum ./*.zip` writes `./name`, which `checksumForAsset` rejected, so `wizard update` failed everywhere from v1.0.10 to v1.0.12. The parser now accepts `./name` and `*name`, and `release.py verify` refuses to publish the `./` form (older clients would break on it).
- **Release channels.** Stable follows GitHub's `releases/latest`; pre-release is "the stable release, unless a release GitHub flags as a pre-release, with a tag `vX.Y.Z-alpha|beta|rc.N`, is newer" (`fetchNewestRelease`). **Never take the highest version in the release list**: the repo still has an older, published, unflagged v2.x line that outranks v1.0.x, and a live run against the real list caught exactly that. The tag grammar and SemVer ordering live in `internal/relver`, and `scripts/release.py`, `install.sh` and `install.ps1` each re-implement the same grammar against the same test table. The chosen channel is `<config dir>/update-channel`; effective channel is chosen > implied by a pre-release build > stable (`resolveChannel`). `update` never downgrades (`releaseUpdateAvailable` is strict SemVer `<`), and Homebrew/Scoop stay stable-only. `wizard channel` needs no checkout so the installers can call it. Pipeline side in [docs/releasing.md](../docs/releasing.md).
- **Package metadata is generated from published checksums, never a local build.** The v1.0.12 Homebrew formula pinned hashes from a local `dist/`, so `brew install` failed with "Formula reports different checksum". `scripts/release.py render` builds the formula and Scoop manifest from the release's own `SHA256SUMS`.
- **Prerequisites are minimums.** Anything at or above Python 3.12 / Node 20 is used as is (searched on PATH, Homebrew, user bins and Node version-manager directories, all after the user's own PATH). Missing tools are installed as the current release, falling back to the minimum-version package; tables live in `prereqs.go` and a test pins the rule. Keg-only Homebrew formulae (`node@20`) are invisible to PATH, which is what broke `wizard init` on a clean Mac.
- **A tool that exists but cannot exec is not missing.** `checkRunnable` proves a tool runs; ENOEXEC (pnpm 12's shebang-less placeholder) is retried through `sh` by `toolExec`, everything else is reported as broken with its reason.
- **`wizard doctor` is a real diagnostic** (`doctor.go`): read-only, works without a checkout, PASS/WARN/FAIL with a fix, `--json`, exit 3 on failure. `status` is a separate command.
- **Terminal UI.** `internal/ui` decides colour, Unicode and cursor support from the environment and the destination (pipes and CI logs get grep-stable ASCII). `dropdown.go` is a pure state machine plus a thin raw-terminal loop, tested without a terminal; raw mode disables `\n` translation, so anything printed while raw ends in `\r\n`. Init's key entry (`secret.go`) echoes one glyph per character and prints a receipt, never the key. `modelcatalog.go` asks the provider for its models (keys go in headers, never URLs; errors never echo a URL); `initmodels.go` turns that into dropdowns and never asks a person to type a model name or provider URL. Scripted and piped use makes no network calls.
- **Exit codes** are in `internal/exitcode`: 0 ok, 1 failure, 2 usage, 3 environment, 4 network. `--help` exits 0 everywhere.
- **Windows.** `mklink /J` must be started with `SysProcAttr.CmdLine`; Go's argument quoting backslash-escapes the quotes and `cmd.exe` receives garbage. The update helper builds the replacement junction first, swaps by rename and rolls back on failure. The user PATH is edited through the registry (`REG_EXPAND_SZ` kept) and the change broadcast.
