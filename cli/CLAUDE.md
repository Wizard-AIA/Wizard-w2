# CLI daemon — [cli/](cli/)

Moved out of the root `CLAUDE.md` so it loads only when work touches `cli/`.

Milestone 8. A single static Go binary, `wizard`, that manages the backend and frontend as a background service — the primary path now that Milestone 3 made Docker opt-in. `docker compose up` still works; `wizard init && wizard start` is the new one-command path. See [cli/README.md](cli/README.md) for the full subcommand reference and build/cross-compile instructions; this section is the architecture summary.

**Go, not Rust.** Cross-compiles to all three target OSes from one machine via `GOOS`/`GOARCH` with no target toolchain install, `CGO_ENABLED=0` gives a true static binary, and the stdlib (`os/exec`, `net/http`, `os.UserConfigDir`, goroutines) covers process supervision, health polling and log tailing without extra dependencies — the whole job this milestone asks for.

- **`internal/appdir`** is a Go port of `backend/src/utils/appdirs.py`'s `config_dir()`, kept in lockstep by hand since a Go process cannot import the Python module. Same `WIZARD_CONFIG_DIR` override, same per-platform default. Milestone 8 adds `run/` (pid files, the stop sentinel, the crash marker), `logs/` and `venv/` under it, beside `credentials.json`/`connections.json`/`skills/` from earlier milestones.
- **`wizard start` re-execs itself** into a detached, hidden `__supervise` subcommand, so the supervision loop in `internal/daemon` survives the `start` command returning — `start` itself only launches it, polls `/health` until the backend answers, checks the version-compat marker, and opens a browser.
- **The supervisor polls, it doesn't just watch for exit.** A process that hangs without exiting is not caught by "did the child die" — so `internal/daemon.Run` polls `GET /health` (the frontend, which has no equivalent route, gets a bare TCP reachability check instead) and restarts either child with capped exponential backoff on a failure streak, the same as it does on an outright crash. Once the restart budget is exhausted it writes a `crashed` marker and stops trying, rather than either retrying forever or silently going quiet — `wizard status` reads that marker.
- **Per-OS process control is split by build-tag filename** (`process_unix.go` / `process_windows.go`), the same pattern `backend/src/core/security/sandbox/` already uses for the same reason. POSIX: a process group, `SIGTERM` then `SIGKILL`. Windows attempts `CTRL_BREAK_EVENT` first — the same technique `core/tools/host_runtime.py` uses to interrupt one execution — but `GenerateConsoleCtrlEvent` only reaches a process sharing a console with the caller, and the detached, consoleless `__supervise` process this package actually runs as never does; in the shipped binary the stop path is `taskkill /T /F` once the grace period elapses, every time, not "usually graceful."
- **No new backend field for version compatibility.** `internal/compat` compares only the *major* component of `API_VERSION` (`backend/src/api/routes/meta.py`, already reported by both `/health` and `/api/config`) against this binary's build-time compat marker (`-ldflags -X`), so a routine backend patch/minor bump does not force a CLI rebuild. `wizard start` refuses to leave a mismatched pair running.
- **Explicitly out of scope this milestone**, not silently dropped: binary self-update via GitHub Releases (`wizard update` updates the checkout only — no release pipeline exists yet), auto-installing Python/Node/Ollama (`wizard init` detects and prints the install command, never runs a package manager on the user's behalf), and owning the Docker daemon's own lifecycle (`start`/`doctor` only probe reachability; an unreachable Docker under `docker` mode still degrades to `host` exactly as `core/tools/runtime.py` already handles it).
- **No remote access.** The daemon binds `127.0.0.1` only, backend and frontend both — confirmed out of scope by the evolution spec, not a gap.
