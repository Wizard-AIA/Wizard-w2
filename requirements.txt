# CI and the Docker builds install `requirements.lock.txt`, not this file
# directly -- this is the source `uv` compiles from:
#   uv pip compile requirements.txt --universal --generate-hashes \
#     --emit-index-url --python-version 3.11 --output-file requirements.lock.txt
# Regenerate the lock whenever a version here changes; `uv pip install
# --require-hashes` fails loudly if the two drift apart.
#
# What the API server itself needs. Nothing here exists to serve *generated*
# code -- that runs in a sandbox container or a local runtime, and its libraries
# are declared in `requirements-local.txt` and `backend/docker/Dockerfile`.
#
# Deliberately absent:
#   sentence-transformers  pulls torch, which on linux/x86_64 hard-depends on
#                          eleven nvidia-*-cu12 wheels -- ~2.8 GB of compressed
#                          wheels, installed with or without a GPU, to run a
#                          90 MB embedder. Embeddings now come from the model
#                          server the app already talks to. See
#                          `requirements-optional.txt` to put it back.
#   scikit-learn,          used only by generated analysis code, never by the
#   statsmodels, plotly,   API. Installing them here made the server image carry
#   seaborn                a second copy of the sandbox's toolkit.
